9.1 The Web’s Filing Cabinets

PDFs are everywhere in institutional record-keeping: city council minutes, legislative bill texts, financial reports, court filings, academic papers, and environmental impact assessments. They are the format of choice for “official” documents because they look the same on every screen and every printer. The records inside them are what Salganik (2018) calls readymade data: made by institutions for their own purposes, and reusable, with effort, to answer questions their makers never asked.

The City of Boulder keeps thousands of them in its online records portal: signed City Council minutes back to 2000, budgets, ordinances, and the Finance Department’s revenue reports. The revenue report for December 2024 shows both the promise and the problem. Its first pages hold tables of tax revenue whose numbers you can select and copy. Its last page holds a table of sales tax by month for six years that you can’t select at all, because it is a picture of a table. Beside it, the city printed a note: “Please contact sales tax staff … for a screen readable version.”

When you read a PDF, you see paragraphs, tables, headers, and page numbers. A computer reading the same file sees instructions for drawing the page: put these characters at these coordinates, fill this rectangle, paint this image. Getting data out of a PDF is reconstruction, not reading. Software has to infer the words, lines, and tables you see from where things sit on the page, and for a picture of a table, it has to recognize the characters themselves.

So treat the PDF as your last resort, in the same spirit as chapter 8’s order of preference for web pages (Chapter 8):

  1. Look for the data in a form made for machines: an open-data portal, an API, or a spreadsheet.
  2. Ask for it. Colorado’s open-records law says that a record kept in a sortable format, such as a spreadsheet, must be provided in that format (C.R.S. 24-72-203(3.5)).
  3. Parse the PDF.

This chapter is about the third step, which for older records is often the only one available. It starts with the concepts and tools: what a PDF stores, how to tell which kind of PDF you have, how to get the files, what pypdf, pdfplumber, and OCR each reconstruct, and how to check that an extraction is right. Two case studies from Boulder then use all of them: council minutes for text, and revenue reports for tables. The chapter ends with AI document parsers, and with how to judge one.

NotePublic Interest Connection

When governments publish minutes, budgets, and filings only as PDFs, they create what Chapter 3 calls “soft enclosure”: records that are public in name and hard to analyze in practice. A picture of a table is the extreme case, because neither a screen reader nor a script can read its numbers. Building the skills to extract data from PDFs serves the oversight value: it lets people outside an institution analyze its records for themselves.

9.1.1 This Chapter’s Files

The chapter’s code reads copies of the city’s PDFs that the book keeps on GitHub, so that a class of readers doesn’t send hundreds of requests to the city’s server at once. “Getting the Files,” below, shows where the copies came from and how to download from the portal yourself. Each file downloads once, the first time you ask for it:

import requests
from pathlib import Path

# The book's copies of this chapter's files; data/ch-09/manifest.csv says where each one came from
BOOK_DATA = "https://raw.githubusercontent.com/cuinfoscience/Web-Data-Science-Book/main/data/ch-09/"
# Say who is asking, as chapter 2 recommends; put your own email address here
HEADERS = {"User-Agent": "WebDataScience/1.0 (your-email@colorado.edu)"}
# The folder, next to your notebook, where the files are saved
PDF_DIR = Path("pdfs")

def get_saved_copy(name):
    """Return the path of one of the book's saved files, downloading it the first time.

    Parameters
    ----------
    name : str
        A file name in the book's data/ch-09 folder, such as "revenue-report-2024-12.pdf"

    Returns
    -------
    pathlib.Path
        Where the file is on your computer
    """
    path = PDF_DIR / name
    if not path.exists():                  # download only the first time
        PDF_DIR.mkdir(exist_ok=True)       # make the folder if it isn't there yet
        response = requests.get(BOOK_DATA + name, headers=HEADERS, timeout=60)
        response.raise_for_status()        # stop with an error if the download failed
        path.write_bytes(response.content) # a PDF is bytes, not text, so save the bytes as they came
    return path

# The December 2024 revenue report, which the next sections read
report_2024 = get_saved_copy("revenue-report-2024-12.pdf")
print(report_2024, f"{report_2024.stat().st_size:,} bytes")  # the file's size, with commas
# pdfs/revenue-report-2024-12.pdf 723,920 bytes

9.2 What’s Inside a PDF

A PDF page is a list of drawing instructions, which the format calls a content stream. Three kinds of things get drawn:

  • Characters. Each instruction picks a font and a size and places characters at a position. The font maps each character’s shape to the Unicode character it stands for. When that map is missing or wrong, extraction returns gibberish from a page that looks fine.
  • Lines and rectangles: rules, borders, shading, and the grid of a table.
  • Images: logos, photographs, charts, and, in a scanned document, the whole page.

What most PDFs don’t store is any of the structure you see: words, lines of text, paragraphs, columns, tables, or the order in which to read them. The gap between two words may be a space character, or just a wider gap between two characters. Everything else is inferred from position.

You can see this with pdfplumber, which lists every object on a page with its coordinates. Positions are in points, 1/72 of an inch, measured from the page’s left edge (x0) and its top (top):

import pdfplumber

# "with" opens the file and closes it again at the end of the block
with pdfplumber.open(report_2024) as pdf:
    page = pdf.pages[1]  # the second page, where the report's tables start
    print(len(pdf.pages), "pages; this one is", page.width, "by", page.height, "points")
    # page.chars is a list with one dictionary per character; print seven of them
    for char in page.chars[1:8]:
        # The character, its distance from the left edge and from the top, its font, and its size
        print(repr(char["text"]), round(char["x0"], 1), round(char["top"], 1), char["fontname"], round(char["size"], 1))
    # How many of each kind of object the page draws
    print(len(page.chars), "characters,", len(page.lines), "lines,", len(page.rects), "rectangles,", len(page.images), "images")

The first seven characters spell “City of”, one character at a time. Each carries its own position, font, and size, and “City” is a word only because its four characters sit close together. The table’s rules aren’t lines at all: they are hundreds of thin, filled rectangles (Figure 9.1). Any tool that finds a table on this page has to rebuild its grid from those rectangles, and its cells from the characters.

Metadata. A PDF also stores facts about itself: a title, an author, the program that made it, and dates. pypdf reads them:

from pypdf import PdfReader

reader = PdfReader(report_2024)  # open the report with pypdf
meta = reader.metadata           # the facts the file stores about itself
print(meta.title, "|", meta.subject, "|", meta.creator, "|", meta.creation_date)
# REVENUE REPORT | March 2018 | Acrobat PDFMaker 25 for Word | 2025-05-01 13:20:25-06:00

The title and the creator look right. The subject, March 2018, in a report on December 2024, came from the Word template the report started from: five of the city’s seven year-end reports carry it. Metadata says what the software wrote, not what is true, so don’t date a document by it. The creator is worth reading, though, because it tells you how the file was made, which is what the next section is about.

Tagged PDFs. Some PDFs carry a second layer for assistive technology: a structure tree that marks headings, paragraphs, tables, and figures, sets the reading order, and holds alternative text, which a screen reader speaks in place of an image. PDF/UA (ISO 14289-1) is the standard for doing this well. Six of the seven year-end reports are tagged. In the December 2024 report, the picture of the monthly table has alternative text, and it reads the note again: “This table presents historical taxes by type. Please contact sales tax staff … for a screen readable version.” In December 2021, the three pictures of tables say what Word writes when nobody writes anything: “Table. Description automatically generated.” Tagging can make a PDF accessible, but only when someone fills it in.

NoteAside: Where PDF Came From, and What’s in the File

PDF grew out of a printer language. In 1984 Adobe released PostScript, a programming language for describing pages: a laser printer ran a PostScript program, and the program drew the page. Around 1990, John Warnock, one of Adobe’s founders, wrote a six-page paper called “The Camelot Project” (Adobe’s account). If every computer could display and print the same page description, he argued, people could send each other documents that looked the same everywhere. Adobe released Acrobat and version 1.0 of the Portable Document Format on June 15, 1993. PDF kept PostScript’s way of drawing a page, with fonts, coordinates, lines, and images, and dropped the programming: a PDF page is a fixed list of instructions rather than a program to run. From 1994 Adobe gave Acrobat Reader away, and it published the specification, so anyone could write software that reads or writes PDFs. That is why this chapter’s files come from so many makers: Word’s PDFMaker, Acrobat Distiller, a Canon scanner, and, for the minutes of 2000, the records portal itself.

The file is a set of numbered objects: dictionaries, arrays, numbers, and strings, plus streams of compressed bytes, such as fonts, images, and each page’s drawing instructions. A cross-reference table records where each object starts, so a viewer can jump to page 15 without reading pages 1 to 14; since PDF 1.5 (2003) the table can itself be a compressed stream, as it is in this report. A viewer starts at the end of the file, whose last lines say where that table is (pypdf’s guide to the format walks through the parts). Each page object points to the fonts, images, and content stream it uses. Here are the December 2024 report’s first bytes, and the instructions that draw its running title on page 2:

The header names the format and its version. The first object says the file is linearized, which Acrobat calls “Fast Web View”: 723,920 bytes long, with 15 pages, arranged so that the first page’s objects come first and a browser can show page 1 while the rest downloads. In the content stream, Tf picks the font /TT0, Arial Bold. The six letters before the plus sign in its name mark a subset: the file holds only the characters the report uses. Tm sets the size, 11.04 points, and a position 54 points from the left edge and 767.28 up from the bottom, since PDF counts up from the bottom where pdfplumber’s top counts down. After a space, TD moves down a line, and TJ draws the strings in its brackets. “City of Boulder” is stored as nine pieces, C, i, t, y o, and so on, with the numbers between them nudging each piece into place. Nothing marks the three words as words, or the line as a title.

Later versions added what the first lacked. Linearization came with PDF 1.2 in 1996. PDF 1.3 added a structure tree, and PDF 1.4 added tagged PDF in 2001: the rules for using that tree to record the headings, reading order, and alternative text described above. Tags are optional, so software that makes PDFs could leave them out, and much of it did. PDF became an ISO standard in 2008, as ISO 32000-1, and PDF 2.0 followed as ISO 32000-2 in 2017. Two narrower standards build on it: PDF/A for archives (ISO 19005, from 2005), which requires every font to be embedded and forbids encryption, so a file still opens decades later; and PDF/UA for accessibility (ISO 14289, from 2012), which requires tags.

The same design explains why institutions publish PDFs and why analysts struggle with them. A PDF looks the same on every screen and printer, carries its own fonts, can be signed, and can be kept for decades, which suits a record that must not change. But it describes a printed page, not a document: it doesn’t reflow on a phone, it keeps its structure only when someone tags it, and it hands a script positions instead of words. Adobe added a reading mode for phones, Liquid Mode, in 2020. The UK’s Government Digital Service drew a different conclusion in 2018: GOV.UK’s content should be HTML by default, not PDF, because a PDF doesn’t fit the browser’s window and is harder to find, use, keep up to date, and make accessible. The chapter’s last section returns to what the trade costs the public.

9.3 What Kind of PDF Is It?

Chapter 8 began with three checks for whether a page needs a browser (Chapter 8). A PDF needs the same kind of triage before you extract anything, because the right tool depends on how each page was made. There are three kinds:

  • Born-digital pages come from software, such as Word or a print-to-PDF driver, which writes the characters into the file. The text is there to extract, though its structure must still be rebuilt.
  • Scanned pages are pictures of paper. The file holds an image and no characters, so text extraction returns nothing. You need optical character recognition (OCR), which reads characters from the image.
  • Scanned with a text layer: someone, often the scanner itself, already ran OCR and hid the text it recognized behind the image. The page looks like a scan, and extraction returns text, but that text is only as good as the OCR that made it.

Files mix them. Boulder’s revenue reports are born-digital, but their charts, and in some years their tables, are pictures.

Check 1: try to select the text. Open the PDF in a viewer and drag across a line. If the text highlights word by word, the page has characters. If nothing highlights, or the whole page highlights as one block, it’s an image.

Check 2: count characters and images on every page. This is check 1 done in code, for every page at once:

def page_profile(path):
    """Count the characters of extracted text, and the images, on each page of a PDF.

    Returns two lists, characters and images, with one number per page.
    """
    reader = PdfReader(path)
    characters = []
    images = []
    for page in reader.pages:
        characters.append(len(page.extract_text()))  # how much text the page gives
        images.append(len(page.images))              # how many pictures it holds
    return characters, images

for name in ["revenue-report-2024-12.pdf", "revenue-report-2018.pdf", "council-minutes-2018-12-04.pdf"]:
    characters, images = page_profile(get_saved_copy(name))
    print(name)
    print("  characters:", characters)
    print("  images:    ", images)

9.4 Getting the Files

The saved copies came from the city’s records portal, documents.bouldercolorado.gov, which runs Laserfiche WebLink, software that many local governments use for their records. Open the Revenue Reports folder in a browser and you’ll see four year folders and three annual reports. View Source shows almost none of it: the page is a shell that says “Loading…”, and JavaScript fills in the list. Chapter 8’s way of finding a hidden API (Chapter 8, “Check 3: Watch the Network Tab”) shows where the list comes from: a request named GetFolderListing2, which sends the folder’s number and gets back JSON.

ImportantCertificates and public records

HTTPS checks a certificate, which proves that a server is who it claims to be. Public data isn’t exempt: some government servers are set up in ways that browsers forgive and Python doesn’t, and Boulder’s is one of them. Its first answer to Python is likely an SSLError that mentions CERTIFICATE_VERIFY_FAILED. The cells below pass verify=bundle, a file of certificates that the book provides, and the request goes through. Never use verify=False, which turns the check off. “Appendix: Technical Notes”, at the end of the chapter, explains what is missing and how the bundle was made.

These two cells are the chapter’s only requests to the city’s server. Run them at home, not all at once in class: on October 6, 2026, the server stopped answering after 13 to 17 requests in a row, whether they came 30 or 60 seconds apart, and answered again after a five-minute pause. The first cell asks for the Revenue Reports folder’s list, as the folder page does:

import time

# The certificates to check the city's server against (see the note above)
bundle = get_saved_copy("boulder-ca-bundle.pem")
PORTAL = "https://documents.bouldercolorado.gov/WebLink/"

# The JSON the folder page itself sends: 194345 is the Revenue Reports folder
body = {"repoName": "LF8PROD2", "folderId": 194345, "getNewListing": True,

    else:

9.5.1 Cleanup Strategies

You can repair some of the damage with regular expressions, as long as you match what the extraction produced rather than what the page shows. A pattern for “Page 1” would miss pypdf’s “P age 1”:

import re

def clean_page_text(raw_text):
    """Clean text that pypdf extracted from a page of the council minutes.

    Parameters
    ----------
    raw_text : str
        Raw text from PdfReader.pages[n].extract_text()

    Returns
    -------
    str
        Cleaned text with normalized spacing, line breaks preserved
    """
    # Drop the page number, which pypdf reads from these minutes as "P age 1"
    text = re.sub(r'^P ?age \d+[ \t]*$', '', raw_text, flags=re.MULTILINE)

    # Rejoin a first letter that Word drew apart from the rest of its word: "M" and "ayor" become "Mayor"
    text = re.sub(r'\b([A-Z]{1,2})\n(?=[A-Za-z])', r'\1', text)

    # Collapse runs of spaces and tabs, but NOT newlines. Line structure is real information in extracted PDF text (headings sit on their own lines), so we keep it
    text = re.sub(r'[ \t]+', ' ', text)

    # Strip each line and drop lines left empty by the removals above
    kept = []
    for line in text.split('\n'):
        line = line.strip()
        if line:
            kept.append(line)
    return '\n'.join(kept)  # put the lines back together, one per line

cleaned = clean_page_text(text)  # text: page 1 of the December 5 minutes, from the cell above
for line in cleaned.splitlines()[:8]:
    print(line)
# CITY COUNCIL MEETING
# Council Chambers
# Thursday, December 5, 2024
# MINUTES
# 1. Call to Order and Roll Call:
# Mayor Brockett called the meeting to order at 6:00 p.m.
# Council Members present: Benjamin, Brockett, Folkerts, Marquis, Schuchard,
# Speer, Wallach, Winer

The most important choice in this function is what not to collapse. A tempting one-liner is re.sub(r'\s+', ' ', raw_text), which normalizes all whitespace in a single pass — but \s matches newlines too, and flattening the page into one long line destroys structure you will need later. Section headings, for example, are recognizable precisely because they sit alone on their own lines; erase the newlines and no heading detector can find them. Collapsing only spaces and tabs ([ \t]+) tidies the text while keeping its shape.

The second rule is a guess about this source: a line that ends in one or two capital letters, followed by a line that starts with a letter, is one word cut in two. On these minutes the guess holds. Across the eight pages it rejoins 39 words, and each was a real break. On the minutes of December 7, 2023, one of its 30 joins is wrong. A motion “to ACCEPT consent agenda items A-F” sits beside the table cell that names who made and seconded it, pypdf puts the two on consecutive lines, and the rule joins “A-F” to “Wallach” as “A-FWallach”. The same page breaks “Call-Up” into “Ca” and “ll-Up”, which the rule doesn’t catch at all. Check a repair written for one file on the next, and print what it changed.

9.5.2 Regular Expressions for PDF Text

Regular expressions are your main tool for imposing structure on the text that comes out of a PDF. Where structured data formats give you fields and columns, PDF text gives you lines of characters, and a pattern carves out the pieces you need. Here are five, run on all eight pages of the December 5 minutes:

# Join the text of all eight pages, then clean it once
page_texts = []
for page in minutes_2024.pages:
    page_texts.append(page.extract_text())
full_text = clean_page_text("\n".join(page_texts))

# re.findall() returns every match of a pattern, as a list

# 1. Dates written out, as the minutes write most of them ("December 5, 2024")
MONTH = r'(?:January|February|March|April|May|June|July|August|September|October|November|December)'
print(re.findall(MONTH + r' \d{1,2}, \d{4}', full_text))

# 2. Dates with slashes, which the minutes also use ("12/19/24")
print(re.findall(r'\d{1,2}/\d{1,2}/\d{2,4}', full_text))

# 3. Clock times ("6:00 p.m."): print the first, the last, and how many
times = re.findall(r'\d{1,2}:\d{2} [ap]\.m\.', full_text)
print(times[0], "to", times[-1], f"({len(times)} times in all)")

# 4. Vote tallies in the motion tables ("Carried 9:0"); each group in parentheses becomes one part of a match
print(re.findall(r'(Carried|Failed) (\d+):(\d+)', full_text))

# 5. Dollar amounts ("$20,000,000")
print(re.findall(r'\$[\d,]+(?:\.\d{2})?', full_text))
# ['December 5, 2024', 'November 5, 2024', 'November 5, 2024']
# ['12/05/24', '12/19/24']
# 6:00 p.m. to 10:43 p.m. (12 times in all)
# [('Carried', '9', '0'), ('Carried', '9', '0')]
# ['$20,000,000']

Each pattern assumes something about the document. The minutes write most dates out in words, so a slash pattern alone would find two of the five. The tally pattern finds the two votes recorded in motion tables and misses the votes recorded in sentences, such as “by a vote of 9:0”. The dollar pattern assumes a leading $; budget documents that put negative values in parentheses need more. Test a pattern on several pages and several documents from the same source before you build on it, and count what it misses as well as what it finds.

9.6.1 Finding Tables

A table in a PDF is characters that line up, usually with rules or shaded boxes around them, and pdfplumber’s table finder rebuilds the grid. By default it uses the lines strategy: it collects the page’s rules and the sides of its rectangles, joins those that nearly touch, and makes a cell wherever horizontal and vertical rules close a box. The text strategy infers columns from words that line up instead. Start with the summary page of the December 2024 report:

import pandas as pd

def summary_frame(rows, columns, label="source"):
    """Turn the rows of a table of labeled figures into a DataFrame.

    Parameters
    ----------
    rows : list of lists
        The table, as pdfplumber's extract() or extract_table() returns it
    columns : dict
        Each column's name and its position in a row, such as {"source": 1, "ytd_2023": 3};
        every column but the label holds figures
    label : str
        The name, in columns, of the column that holds each row's label

    Returns
    -------
    pandas.DataFrame
        One row for each row with a label and a first figure; header rows and section titles are left out
    """
    # The figure columns: every column but the label, in the order columns lists them
    figure_columns = []
    for name in columns:
        if name != label:
            figure_columns.append(name)
    first_figure = figure_columns[0]

    records = []
    for row in rows:
        # Keep a row only if it has a label and a first figure; that leaves out headers and section titles
        if not row[columns[label]] or not row[columns[first_figure]]:
            continue
        record = {}
        for name, position in columns.items():
            record[name] = row[position]  # the cell in that column
        records.append(record)
    frame = pd.DataFrame(records)
    frame[label] = frame[label].str.replace("\n", " ")  # a label that wraps becomes one line
    for name in figure_columns:
        # Remove dollar signs, commas, and percent signs, then read what is left as a number
        frame[name] = pd.to_numeric(frame[name].str.replace(r"[$,%]", "", regex=True))
    return frame

The table settings. find_tables(), extract_table(), and extract_tables() all take the same dictionary of settings, and any setting you leave out keeps its default. The ones you are most likely to change, with their defaults in pdfplumber 0.11:

  • vertical_strategy and horizontal_strategy (both "lines") say where column and row boundaries come from:
    • "lines": the page’s rules and the sides of its rectangles;
    • "lines_strict": rules only, ignoring rectangles, such as shaded backgrounds;
    • "text": words that line up;
    • "explicit": positions you give.
  • explicit_vertical_lines and explicit_horizontal_lines (none): the positions, in points, for the "explicit" strategy, as the fix above used for the columns. They can also add boundaries to the ones another strategy finds.
  • snap_tolerance (3 points): parallel rules closer than this are moved to one position, so that a border drawn twice, slightly apart, counts once. snap_x_tolerance and snap_y_tolerance set it for one direction.
  • join_tolerance (3 points): pieces of a rule whose ends are this close are joined into one, so that a border drawn in segments counts as a single line.
  • edge_min_length (3 points): rules shorter than this are dropped before the grid is built, which leaves out underlines and tick marks.
  • intersection_tolerance (3 points): how close a horizontal and a vertical rule must come to count as crossing, and so to make the corner of a cell.
  • min_words_vertical (3) and min_words_horizontal (1): for the "text" strategy, how many words must line up to make a column boundary or a row boundary. Raise min_words_vertical when a short run of aligned words makes a column that isn’t there.
  • text_x_tolerance and text_y_tolerance (3 points each): for the "text" strategy, how far apart letters can be and still count as one word, and how far up or down and still count as one line.

To see what a set of settings finds, draw it: page.to_image().debug_tablefinder(settings) outlines the cells and marks the crossings, as in Figure 9.3. pdfplumber’s documentation lists every setting, with more on each: Table-extraction settings.

9.7 When There Is No Text Layer: OCR

Optical character recognition (OCR) turns a picture of text into characters. An OCR engine finds the parts of a page that hold text, splits them into lines and words, and recognizes each character from its shape, using a model of the language to settle close calls. It works best on sharp, straight, high-contrast images of at least 300 dots per inch. Tesseract, an engine that Hewlett-Packard built between 1985 and 1994, partly in Greeley, Colorado, and that Google developed from 2006, is the standard open-source choice. pytesseract runs Tesseract from Python; both were installed under “Installing pypdf, pdfplumber, and pytesseract”, at the start of the chapter.

Tesseract reads most figures right, and gets the punctuation of a few wrong: periods for commas in “7,608.759” and “11.242.614”, and a stray dash before the second. The figures are whole dollars, so commas and periods can both be dropped. A stray mark that breaks a row’s pattern is harder, so set those rows aside and report them:

NUMBER = r"[—–-]?\d[\d.,]*"  # a figure as OCR may read it, with a stray dash, or periods for commas
# A row: an optional category name, a year, then 13 figures (twelve months and the year's total)
ROW = re.compile(r"^(?P<label>[A-Za-z ]*?)\s*(?P<year>20\d\d)\s+(?P<figures>(?:" + NUMBER + r"\s+){13})")

def ocr_dollars(figure):
    """'8.832.480' -> 8832480. The table's dollar figures are whole and positive, so every other character can go."""
    return int(re.sub(r"\D", "", figure))  # \D: anything that isn't a digit

ocr_rows = []   # the rows that parsed
set_aside = []  # lines with a year that didn't parse
category = None # the tax the current rows belong to
for line in ocr_lines:
    match = ROW.match(line)
    if not match:
        if re.search(r"\b20\d\d\b", line):
            set_aside.append(line)  # a line with a year that didn't parse: keep it to look at
        continue                    # go on to the next line
    if match["label"].strip():
        category = match["label"].strip()  # each category's name starts its first row
    figures = []
    for figure in match["figures"].split():
        figures.append(ocr_dollars(figure))
    # The first twelve figures are the months, and the thirteenth is the year's total
    ocr_rows.append({"category": category, "year": int(match["year"]), "months": figures[:12], "total": figures[12]})

print(len(ocr_rows), "rows parsed;", len(set_aside), "set aside")

    print(" ".join(line.split()[:6]))  # the start of each line set aside

# ” 2022 489,417 405,726 646,263 552.449
# 2022 12,289,385 11,703,828 14,650,181 — 13,712,583

9.8 Checking an Extraction

Extraction fails without errors. pdfplumber dropped the summary table’s totals row and raised nothing. The tally pattern found two votes and said nothing about the others. Tesseract read periods for commas, and its confidence scores flagged one such figure and passed another. Each of these was caught by a check, and checks are cheap: most take a line or two of code. Here they are, cheapest first, each with its example from this chapter:

  1. Look at the page beside the output. The debug image showed where the table ended (Figure 9.3), and the scan of page 7 of the 2018 minutes showed that Tesseract read the motion right.
  2. Count. You know how many rows the page shows. The summary table has nine rows of figures, Exhibit 3 has 30, and the council has nine seats.
  3. Types and ranges. Every figure should parse as a number, and a value far outside the others gets a look. Exhibit 3 says that business use tax’s taxable sales changed by 615.01% in 2019. The image says the same as the OCR, so the question goes to the city, not to Tesseract.
  4. Sums. Parts should add up to their totals, within a tolerance for rounding. The summary table’s five sources add up to $171,006,200, and the subtotal printed beneath them is $171,006,199.
  5. Two tools agree. pypdf’s text and pdfplumber’s table, read from the same page, should give the same figures.
  6. Two documents agree. OCR’s 2024 total from Exhibit 3 should equal the summary page’s, which is text. Reports that overlap should agree too: the December 2023 and December 2024 reports both print 2023’s figures, and all 12 match.
  7. A sample coded by hand. For text, such as the names in an attendance list, read a sample of pages yourself and measure the extraction against it.
  8. A record of what you did. Keep the manifest of files and hashes, the versions of the libraries, and the date of each run, so that someone else can audit your work and redo it.

Write the checks as a function that returns a list of problems, so a pipeline can run them on every file and report what failed, instead of stopping at the first error or carrying on in silence:

def check_summary(table, tolerance=5):
    """Check the revenue summary table's figures against each other.

    Parameters
    ----------
    table : pandas.DataFrame
        The table, from summary_frame()
    tolerance : int
        How many dollars a sum may miss by; the report rounds each figure to the dollar

    Returns
    -------
    list of str
        One line for each failed check; an empty list means every check passed
    """
    problems = []

    # Count: the page shows nine rows of figures
    if len(table) != 9:
        problems.append(f"expected 9 rows of figures, found {len(table)}")

    # Look up rows by their labels from here on
    figures = table.set_index("source")
    subtotal = "Total Sales & Use Tax based on current economic activity"
    total = "Total Sales and Use Tax"
    for label in [subtotal, total]:
        if label not in figures.index:
            problems.append(f"no row labeled {label!r}")
    if problems:
        return problems  # the sums below need every row

    # Sums, for each year: the parts should add up to the subtotal, and the subtotal and audits to the total
    for year in ["ytd_2023", "ytd_2024"]:
        sources = figures[year].iloc[:5].sum()  # the five sources above the subtotal
        if abs(sources - figures.loc[subtotal, year]) > tolerance:
            problems.append(f"{year}: the sources add up to {sources:,}, not {figures.loc[subtotal, year]:,}")
        audits = figures.loc["Sales Tax Audit Revenue", year] + figures.loc["Use Tax Audit Revenue", year]
        if abs(figures.loc[subtotal, year] + audits - figures.loc[total, year]) > tolerance:
            problems.append(f"{year}: the subtotal and audit revenue don't add up to the total")
    return problems

def split_names(names):
    """Split a list of surnames such as "Speer, Wallach, and Winer" into a set."""
    names = re.sub(r"\b([A-Z]) ([a-z]+)", r"\1\2", names)  # pypdf's "S peer" is "Speer"
    surnames = set()
    # Split at each comma and at each word "and"
    for name in re.split(r",|\band\b", names):
        if name.strip():
            surnames.add(name.strip())
    return surnames

def roll_call(page_1):
    """Find the members present at a meeting's roll call.

    Parameters
    ----------
    page_1 : str
        The cleaned text of page 1 of a meeting's minutes

    Returns
    -------
    set of str
        The surnames of the members present, in the room or online
    """
    present = set()

    # The mayor calls the meeting to order; through 2020, the list of members leaves the mayor out
    mayor = re.search(r"Mayor (\w+) called the meeting to order", page_1)
    if mayor:
        present.add(mayor.group(1))

    # 2018-2020: "Council Members Brockett, Carlisle, ... and Young were present"
    sentence = re.search(r"Council Members ([A-Z][^:]*?)\s+were\s+present", page_1)
    if sentence:
        present |= split_names(sentence.group(1))  # "|=" adds the names to the set

    # 2021-2024: "Council Members present: ...", "Virtually present: ...", "Present virtually: ..."
    lines = page_1.splitlines()
    for i, line in enumerate(lines):
        label = re.match(r"(?:.*Members present(?: virtually)?|Virtually present|Present virtually):\s*(.*)", line, re.IGNORECASE)
        if label:
            names = label.group(1)  # the names after the label, on this line
            for following in lines[i + 1:]:
                if not names.endswith(","):
                    break  # a list that goes on to the next line ends this one with a comma
                names += " " + following
            present |= split_names(names)
    return present

“Finding Tables” showed that pdfplumber’s table finder leaves out the totals row on the December 2024 page, because the row has no vertical rules beside it. The other reports’ tables have different rules, and each would need its own settings. One row is all this question needs, though, and pdfplumber can find a row without finding the table: search() returns where a phrase sits on the page, and a crop of the page from the left edge to the right, as tall as that line, holds the row’s words. The column headings work the same way: the two years sit side by side above the figures.

def row_words(page, label):
    """Return the words to the right of label, on the line where label is.

    Parameters
    ----------
    page : pdfplumber.page.Page
        The page to read
    label : str
        A regular expression for the row's label, such as "Total Sales and Use Tax"

    Returns
    -------
    list of str
        The row's other words, from left to right
    """
    found = page.search(label)[0]  # the first match: its text, and its position in points
    # A strip of the page, across its whole width, from just above the label to just below it
    line = page.crop((0, found["top"] - 1, page.width, found["bottom"] + 1))
    words = []
    for word in line.extract_words():
        if word["x0"] > found["x1"]:  # the word starts right of where the label ends
            words.append(word["text"])
    return words

def to_number(text):
    """Turn a figure such as "$134,538,892", "(1,145,528)", or "-$1,608,698" into an int."""
    negative = text.startswith(("(", "-"))   # accountants write a negative number in parentheses
    value = int(re.sub(r"[^\d]", "", text))  # keep only the digits
    if negative:
        return -value
    return value

9.11 Document Understanding

Everything so far rebuilds a page step by step, and you choose each step: which library reads the text layer, where a table’s columns are, which rows to set aside. Document understanding is the research field that tries to read a document as a whole. Its tasks include layout analysis, which finds the headings, paragraphs, tables, and figures on a page and the order to read them in; table structure recognition, which finds a table’s rows, columns, and merged cells; OCR; and key information extraction, which pulls named fields, such as a date or a total, out of forms and invoices. The Awesome Document Understanding list collects the field’s papers, datasets, and tools.

Its tools usually write Markdown or HTML, because those formats keep a document’s structure, its headings, lists, and tables, as text that a script or a language model (Chapter 13) can read.

9.11.1 Three Kinds of Tools

  • Converters that read the text layer. MarkItDown, from Microsoft, turns PDFs, Word, PowerPoint, Excel, and HTML files into Markdown. For a PDF it reads the text layer, much as pypdf does, so it is fast and needs no model, but a scanned page gives it nothing to read. pymupdf4llm is similar; note its AGPL license, which has conditions for software you distribute.
  • Pipelines of models. A layout model finds the parts of each page, a table model finds each table’s cells, and an OCR engine reads any part that is a picture. Docling, which IBM Research started and the LF AI & Data Foundation now hosts, runs on a laptop’s processor. Marker, from Datalab, and MinerU, from OpenDataLab, work the same way, with a GPU for their best modes.
  • Vision-language models. A model reads an image of the page and writes the whole page out as Markdown or HTML, tables included. Most need an NVIDIA GPU: olmOCR from Ai2, DeepSeek-OCR, Chandra from Datalab, dots.mocr, and PaddleOCR-VL. LightOnOCR-2, at one billion parameters, is small enough to run, slowly, without one. Hosted services, such as Mistral OCR and Datalab’s own API, run the model for you, for a fee per page, after you upload the document.

Pandoc belongs beside these tools but does a different job. It converts between markup formats, such as Markdown, HTML, Word, LaTeX, and EPUB, and Quarto uses it to build this book. Pandoc can write a PDF but can’t read one, so it comes after a parser: pandoc -s summary.md -o summary.html turns a parser’s Markdown into a web page, and -o summary.docx into a Word file.

  • Sums. Of the table’s 30 rows of figures, 21 came out whole, and every one of those adds up to its total.

9.11.3 Judging a Parser

A parser’s benchmark score, such as olmOCR-Bench or OmniDocBench, says how it did on other people’s documents, usually as its own makers report it. On your documents, run the checks from “Checking an Extraction”: count the rows, add up the parts, compare two tools, and code a sample by hand. Then weigh what else the tool costs:

  • Privacy. A hosted service receives your document. So does a local tool when you switch on its cloud options, such as MarkItDown’s language-model and Microsoft Azure features, Marker’s --use_llm, or MinerU’s remote mode. Don’t upload records that hold personal information without permission.
  • Plausible errors. A vision-language model writes text that looks right. Where Tesseract garbles a digit, a model can write a different, well-formed number, or fill in a cell it couldn’t read. Sums and second printings catch these; reading the output does not.
  • Reproducibility. Record the tool’s version and the model’s, as the chapter does for pypdf and pdfplumber. A model that changes can change your data.
  • Time and cost. Docling took a minute for one picture of a table on a laptop’s processor. A thousand pages takes hours without a GPU, or a fee per page from a hosted service.

For the two case studies, the chapter’s own code was the better choice: pypdf and pdfplumber read the text layer exactly, and each step can be checked. Reach for a parser when documents have no text layer, come in many layouts, or are too many to write patterns for, and run the checks on what it produces.

9.14 Social History and Public Interest

The PDF format was created by Adobe in 1993 to solve a real problem: documents needed to look the same regardless of what printer or screen displayed them. But the format’s emphasis on visual fidelity came at the cost of semantic accessibility. Organizations like DocumentCloud, MuckRock, and the Sunlight Foundation have built tools to extract structured data from the flood of PDFs that government agencies produce — bridging the gap between nominally public records and practically accessible data.

DocumentCloud, built by ProPublica and IRE (Investigative Reporters and Editors), emerged as a platform where journalists could upload, analyze, annotate, and share document collections. It has been used in investigations of police misconduct records, corporate fraud filings, and government secrecy — cases where the raw documents are public but the volume makes manual analysis impractical. DocumentCloud’s contribution was not just technical but organizational: it created a shared infrastructure where one journalist’s document processing work could benefit others investigating the same institutions.

MuckRock took a different approach to the document access problem by automating the Freedom of Information Act (FOIA) request process itself. The platform helped journalists and citizens file thousands of public records requests, tracked agency response times, and published the results openly. The Sunlight Foundation, active from 2006 to 2020, advocated for government agencies to publish documents in machine-readable formats rather than PDFs in the first place — arguing that true transparency requires not just publication but usability. Together, these tools and organizations represent the infrastructure of transparency: community-built resources that bridge the gap between nominally public documents and practically accessible data. Their work embodies the ownership value from Chapter 3 — the idea that public records belong to the public, and that technical barriers to access are themselves a form of enclosure that undermines democratic accountability.

The Boulder City Council case illustrates this tension at the local level. The same meeting information could be published as structured data (allowing citizens to easily track attendance, voting patterns, and public comment frequency) or as scanned PDFs (requiring significant technical effort to analyze). The format choice is itself a policy decision with consequences for transparency and accountability. When you build a pipeline that extracts structured data from PDFs, you are not just doing data science — you are doing the work that these organizations have championed for decades.

9.15 Common Issues to Debug

  • Garbled text from scanned PDFs: PyPDF extracts text only from PDFs that have a text layer. Truly scanned documents require OCR tools like Tesseract.
  • Table data extracted as a text stream: PyPDF is not a table extraction tool. For tabular data in PDFs, consider pdfplumber or camelot.
  • Regular expressions that work on one document but fail on another: PDF formatting varies even within documents from the same source. Test your patterns on multiple files.
  • Encoding issues: Some PDFs use non-standard character encodings. Use .encode('utf-8', errors='replace') if needed.

9.16 Key Takeaways

PDFs are designed for visual fidelity, not data extraction. pypdf gives you a page’s text in the order it was drawn; pdfplumber gives you where each word sits, which is what a table needs; and regular expressions impose structure on what either extracts. Expect messiness — PDF extraction is reconstruction, not reading — and check every extraction: against a sample coded by hand, against a second tool, against the document’s own totals, and against a second printing of the same figure. The broader lesson connects to Chapter 3: when institutions publish data only in PDF form, they create a practical barrier to the analysis that nominally public records are meant to enable.

9.18.1 The City’s Server and Its Certificate

Your first request to Boulder’s portal from Python will probably fail with SSLError: … CERTIFICATE_VERIFY_FAILED … unable to get local issuer certificate. A server proves who it is with a chain of certificates: its own, signed by an intermediate certificate, which is signed by a root certificate that your computer already trusts. Boulder’s server sends its own certificate but not the intermediate one. Browsers find the missing certificate by themselves; Python doesn’t.

verify=False would make the error go away by turning off the check that you’re talking to the real server, so don’t use it. The book’s bundle, boulder-ca-bundle.pem, holds the standard root certificates plus that one intermediate, and verify=bundle tells requests to check the server against it. If the city repairs its server, the bundle still works. data/ch-09/make_ca_bundle.py in the book’s repository shows how the bundle was made.

9.18.2 Checking That Two Copies Are the Same File

A hash is a fingerprint of a file’s bytes: change one byte and the hash changes. data/ch-09/manifest.csv records each saved copy’s hash, along with its address on the portal and when it was downloaded. Comparing a file’s hash with the manifest’s says whether you have the same file, byte for byte. If you have run the chapter’s cells in order, you have 18 of the manifest’s 20 files:

import hashlib

manifest = pd.read_csv(get_saved_copy("manifest.csv"))  # one row per saved file
checked = 0
differ = []
for row in manifest.itertuples():
    path = PDF_DIR / row.file
    if not path.exists():
        continue  # check only the files you have downloaded
    digest = hashlib.sha256(path.read_bytes()).hexdigest()  # the file's SHA-256 hash, as text
    checked += 1
    if digest != row.sha256:
        differ.append(row.file)
print(checked, "files checked; hashes that differ:", differ)
# 18 files checked; hashes that differ: []

To check a fresh download from the portal, compute hashlib.sha256(response.content).hexdigest() and compare it with the file’s row. The two scanned minutes from 2000 are the exception: the portal builds a new PDF from their page images for every download, so no two downloads have the same hash.

9.18.3 OCR for a Whole File: OCRmyPDF

pytesseract returns text and leaves the PDF as it was. OCRmyPDF does the whole file: it renders each page, runs Tesseract, and lays the recognized text over the image as an invisible layer, where a viewer can select it and pypdf can extract it.

It is harder to install than the libraries in this chapter, because it is a program that runs other programs, Tesseract among them, and chapter 1’s webdata leaves it out. ## The Web's Filing Cabinets

PDFs are everywhere in institutional record-keeping: city council minutes, legislative bill texts, financial reports, court filings, academic papers, and environmental impact assessments. They are the format of choice for "official" documents because they look the same on every screen and every printer. The records inside them are what @salganik2018bit calls *readymade* data: made by institutions for their own purposes, and reusable, with effort, to answer questions their makers never asked.

The City of Boulder keeps thousands of them in its online records portal: signed City Council minutes back to 2000, budgets, ordinances, and the Finance Department's revenue reports. The revenue report for December 2024 shows both the promise and the problem. Its first pages hold tables of tax revenue whose numbers you can select and copy. Its last page holds a table of sales tax by month for six years that you can't select at all, because it is a picture of a table. Beside it, the city printed a note: "Please contact sales tax staff … for a screen readable version."

When you read a PDF, you see paragraphs, tables, headers, and page numbers. A computer reading the same file sees instructions for drawing the page: put these characters at these coordinates, fill this rectangle, paint this image. Getting data out of a PDF is *reconstruction*, not reading. Software has to infer the words, lines, and tables you see from where things sit on the page, and for a picture of a table, it has to recognize the characters themselves.

So treat the PDF as your last resort, in the same spirit as chapter 8's order of preference for web pages (@sec-dynamic-pages):

1. **Look for the data in a form made for machines**: an open-data portal, an API, or a spreadsheet.
2. **Ask for it.** Colorado's open-records law says that a record kept in a sortable format, such as a spreadsheet, must be provided in that format (C.R.S. 24-72-203(3.5)).
3. **Parse the PDF.**

This chapter is about the third step, which for older records is often the only one available. It starts with the concepts and tools: what a PDF stores, how to tell which kind of PDF you have, how to get the files, what pypdf, pdfplumber, and OCR each reconstruct, and how to check that an extraction is right. Two case studies from Boulder then use all of them: council minutes for text, and revenue reports for tables. The chapter ends with AI document parsers, and with how to judge one.

::: {.callout-note}
## Public Interest Connection
When governments publish minutes, budgets, and filings only as PDFs, they create what @sec-post-api calls "soft enclosure": records that are public in name and hard to analyze in practice. A picture of a table is the extreme case, because neither a screen reader nor a script can read its numbers. Building the skills to extract data from PDFs serves the **oversight** value: it lets people outside an institution analyze its records for themselves.

```{python}
import requests
from pathlib import Path

# The book's copies of this chapter's files; data/ch-09/manifest.csv says where each one came from
BOOK_DATA = "https://raw.githubusercontent.com/cuinfoscience/Web-Data-Science-Book/main/data/ch-09/"
# Say who is asking, as chapter 2 recommends; put your own email address here
HEADERS = {"User-Agent": "WebDataScience/1.0 (your-email@colorado.edu)"}
# The folder, next to your notebook, where the files are saved
PDF_DIR = Path("pdfs")

def get_saved_copy(name):
    """Return the path of one of the book's saved files, downloading it the first time.

    Parameters
    ----------
    name : str
        A file name in the book's data/ch-09 folder, such as "revenue-report-2024-12.pdf"

    Returns
    -------
    pathlib.Path
        Where the file is on your computer
    """
    path = PDF_DIR / name
    if not path.exists():                  # download only the first time
        PDF_DIR.mkdir(exist_ok=True)       # make the folder if it isn't there yet
        response = requests.get(BOOK_DATA + name, headers=HEADERS, timeout=60)
        response.raise_for_status()        # stop with an error if the download failed
        path.write_bytes(response.content) # a PDF is bytes, not text, so save the bytes as they came
    return path

# The December 2024 revenue report, which the next sections read
report_2024 = get_saved_copy("revenue-report-2024-12.pdf")
print(report_2024, f"{report_2024.stat().st_size:,} bytes")  # the file's size, with commas
# pdfs/revenue-report-2024-12.pdf 723,920 bytes
```

## What's Inside a PDF

A PDF page is a list of drawing instructions, which the format calls a *content stream*. Three kinds of things get drawn:

- **Characters.** Each instruction picks a font and a size and places characters at a position. The font maps each character's shape to the Unicode character it stands for. When that map is missing or wrong, extraction returns gibberish from a page that looks fine.
- **Lines and rectangles**: rules, borders, shading, and the grid of a table.
- **Images**: logos, photographs, charts, and, in a scanned document, the whole page.

What most PDFs don't store is any of the structure you see: words, lines of text, paragraphs, columns, tables, or the order in which to read them. The gap between two words may be a space character, or just a wider gap between two characters. Everything else is inferred from position.

You can see this with pdfplumber, which lists every object on a page with its coordinates. Positions are in *points*, 1/72 of an inch, measured from the page's left edge (`x0`) and its top (`top`):

```{python}
import pdfplumber

    # page.chars is a list with one dictionary per character; print seven of them
    for char in page.chars[1:8]:
        # The character, its distance from the left edge and from the top, its font, and its size
        print(repr(char["text"]), round(char["x0"], 1), round(char["top"], 1), char["fontname"], round(char["size"], 1))
    # How many of each kind of object the page draws
    print(len(page.chars), "characters,", len(page.lines), "lines,", len(page.rects), "rectangles,", len(page.images), "images")
# 15 pages; this one is 612.0 by 792.0 points
```

## Aside: Where PDF Came From, and What's in the File

PDF grew out of a printer language. In 1984 Adobe released PostScript, a programming language for describing pages: a laser printer ran a PostScript program, and the program drew the page. Around 1990, John Warnock, one of Adobe's founders, wrote a six-page paper called "The Camelot Project" ([Adobe's account](https://blog.adobe.com/en/publish/2018/06/14/evolution-digital-document-celebrating-adobe-acrobats-25th-anniversary)). If every computer could display and print the same page description, he argued, people could send each other documents that looked the same everywhere. Adobe released Acrobat and version 1.0 of the Portable Document Format on June 15, 1993. PDF kept PostScript's way of drawing a page, with fonts, coordinates, lines, and images, and dropped the programming: a PDF page is a fixed list of instructions rather than a program to run. From 1994 Adobe gave Acrobat Reader away, and it published the specification, so anyone could write software that reads or writes PDFs. That is why this chapter's files come from so many makers: Word's PDFMaker, Acrobat Distiller, a Canon scanner, and, for the minutes of 2000, the records portal itself.

The file is a set of numbered *objects*: dictionaries, arrays, numbers, and strings, plus *streams* of compressed bytes, such as fonts, images, and each page's drawing instructions. A *cross-reference table* records where each object starts, so a viewer can jump to page 15 without reading pages 1 to 14; since PDF 1.5 (2003) the table can itself be a compressed stream, as it is in this report. A viewer starts at the end of the file, whose last lines say where that table is ([pypdf's guide to the format](https://pypdf.readthedocs.io/en/latest/dev/pdf-format.html) walks through the parts). Each page object points to the fonts, images, and content stream it uses. Here are the December 2024 report's first bytes, and the instructions that draw its running title on page 2:


The header names the format and its version. The first object says the file is *linearized*, which Acrobat calls "Fast Web View": 723,920 bytes long, with 15 pages, arranged so that the first page's objects come first and a browser can show page 1 while the rest downloads. In the content stream, `Tf` picks the font `/TT0`, Arial Bold. The six letters before the plus sign in its name mark a *subset*: the file holds only the characters the report uses. `Tm` sets the size, 11.04 points, and a position 54 points from the left edge and 767.28 up from the bottom, since PDF counts up from the bottom where pdfplumber's `top` counts down. After a space, `TD` moves down a line, and `TJ` draws the strings in its brackets. "City of Boulder" is stored as nine pieces, `C`, `i`, `t`, `y o`, and so on, with the numbers between them nudging each piece into place. Nothing marks the three words as words, or the line as a title.

Later versions added what the first lacked. Linearization came with PDF 1.2 in 1996. PDF 1.3 added a structure tree, and PDF 1.4 added *tagged PDF* in 2001: the rules for using that tree to record the headings, reading order, and alternative text described above. Tags are optional, so software that makes PDFs could leave them out, and much of it did. PDF became an ISO standard in 2008, as ISO 32000-1, and PDF 2.0 followed as ISO 32000-2 in 2017. Two narrower standards build on it: PDF/A for archives (ISO 19005, from 2005), which requires every font to be embedded and forbids encryption, so a file still opens decades later; and PDF/UA for accessibility (ISO 14289, from 2012), which requires tags.

The same design explains why institutions publish PDFs and why analysts struggle with them. A PDF looks the same on every screen and printer, carries its own fonts, can be signed, and can be kept for decades, which suits a record that must not change. But it describes a printed page, not a document: it doesn't reflow on a phone, it keeps its structure only when someone tags it, and it hands a script positions instead of words. Adobe added a reading mode for phones, Liquid Mode, in 2020. The UK's Government Digital Service drew a different conclusion in 2018: GOV.UK's content should be [HTML by default, not PDF](https://gds.blog.gov.uk/2018/07/16/why-gov-uk-content-should-be-published-in-html-and-not-pdf/), because a PDF doesn't fit the browser's window and is harder to find, use, keep up to date, and make accessible. The chapter's last section returns to what the trade costs the public.

## What Kind of PDF Is It?

Chapter 8 began with three checks for whether a page needs a browser (@sec-dynamic-pages). A PDF needs the same kind of triage before you extract anything, because the right tool depends on how each page was made. There are three kinds:

- **Born-digital** pages come from software, such as Word or a print-to-PDF driver, which writes the characters into the file. The text is there to extract, though its structure must still be rebuilt.
- **Scanned** pages are pictures of paper. The file holds an image and no characters, so text extraction returns nothing. You need *optical character recognition* (OCR), which reads characters from the image.
- **Scanned with a text layer**: someone, often the scanner itself, already ran OCR and hid the text it recognized behind the image. The page looks like a scan, and extraction returns text, but that text is only as good as the OCR that made it.

Files mix them. Boulder's revenue reports are born-digital, but their charts, and in some years their tables, are pictures.

**Check 1: try to select the text.** Open the PDF in a viewer and drag across a line. If the text highlights word by word, the page has characters. If nothing highlights, or the whole page highlights as one block, it's an image.

### Cleanup Strategies

You can repair some of the damage with regular expressions, as long as you match what the extraction produced rather than what the page shows. A pattern for "Page 1" would miss pypdf's "P age 1":

```{python}
import re

def clean_page_text(raw_text):
    """Clean text that pypdf extracted from a page of the council minutes.

    Parameters
    ----------
    raw_text : str
        Raw text from PdfReader.pages[n].extract_text()

    Returns
    -------
    str
        Cleaned text with normalized spacing, line breaks preserved
    """
    # Drop the page number, which pypdf reads from these minutes as "P age 1"
    text = re.sub(r'^P ?age \d+[ \t]*$', '', raw_text, flags=re.MULTILINE)

    # Rejoin a first letter that Word drew apart from the rest of its word: "M" and "ayor" become "Mayor"
    text = re.sub(r'\b([A-Z]{1,2})\n(?=[A-Za-z])', r'\1', text)

    # Collapse runs of spaces and tabs, but NOT newlines. Line structure is real information in extracted PDF text (headings sit on their own lines), so we keep it
    text = re.sub(r'[ \t]+', ' ', text)

    # Strip each line and drop lines left empty by the removals above
    kept = []
    for line in text.split('\n'):
        line = line.strip()
        if line:
            kept.append(line)
    return '\n'.join(kept)  # put the lines back together, one per line

cleaned = clean_page_text(text)  # text: page 1 of the December 5 minutes, from the cell above
for line in cleaned.splitlines()[:8]:
    print(line)
# CITY COUNCIL MEETING
# Council Chambers
# Thursday, December 5, 2024
# MINUTES
# 1. Call to Order and Roll Call:
# Mayor Brockett called the meeting to order at 6:00 p.m.
# Council Members present: Benjamin, Brockett, Folkerts, Marquis, Schuchard,
# Speer, Wallach, Winer
```

The most important choice in this function is what *not* to collapse. A tempting one-liner is `re.sub(r'\s+', ' ', raw_text)`, which normalizes all whitespace in a single pass — but `\s` matches newlines too, and flattening the page into one long line destroys structure you will need later. Section headings, for example, are recognizable precisely because they sit alone on their own lines; erase the newlines and no heading detector can find them. Collapsing only spaces and tabs (`[ \t]+`) tidies the text while keeping its shape.

The second rule is a guess about this source: a line that ends in one or two capital letters, followed by a line that starts with a letter, is one word cut in two. On these minutes the guess holds. Across the eight pages it rejoins 39 words, and each was a real break. On the minutes of December 7, 2023, one of its 30 joins is wrong. A motion "to ACCEPT consent agenda items A-F" sits beside the table cell that names who made and seconded it, pypdf puts the two on consecutive lines, and the rule joins "A-F" to "Wallach" as "A-FWallach". The same page breaks "Call-Up" into "Ca" and "ll-Up", which the rule doesn't catch at all. Check a repair written for one file on the next, and print what it changed.

### Regular Expressions for PDF Text

Regular expressions are your main tool for imposing structure on the text that comes out of a PDF. Where structured data formats give you fields and columns, PDF text gives you lines of characters, and a pattern carves out the pieces you need. Here are five, run on all eight pages of the December 5 minutes:

```{python}
# Join the text of all eight pages, then clean it once
page_texts = []
for page in minutes_2024.pages:
    page_texts.append(page.extract_text())
full_text = clean_page_text("\n".join(page_texts))

# re.findall() returns every match of a pattern, as a list

# 1. Dates written out, as the minutes write most of them ("December 5, 2024")
MONTH = r'(?:January|February|March|April|May|June|July|August|September|October|November|December)'
print(re.findall(MONTH + r' \d{1,2}, \d{4}', full_text))

# 2. Dates with slashes, which the minutes also use ("12/19/24")
print(re.findall(r'\d{1,2}/\d{1,2}/\d{2,4}', full_text))

# 3. Clock times ("6:00 p.m."): print the first, the last, and how many
times = re.findall(r'\d{1,2}:\d{2} [ap]\.m\.', full_text)
print(times[0], "to", times[-1], f"({len(times)} times in all)")

# 4. Vote tallies in the motion tables ("Carried 9:0"); each group in parentheses becomes one part of a match
print(re.findall(r'(Carried|Failed) (\d+):(\d+)', full_text))

# 5. Dollar amounts ("$20,000,000")
print(re.findall(r'\$[\d,]+(?:\.\d{2})?', full_text))
# ['December 5, 2024', 'November 5, 2024', 'November 5, 2024']
# ['12/05/24', '12/19/24']
# 6:00 p.m. to 10:43 p.m. (12 times in all)
# [('Carried', '9', '0'), ('Carried', '9', '0')]
# ['$20,000,000']
```

Each pattern assumes something about the document. The minutes write most dates out in words, so a slash pattern alone would find two of the five. The tally pattern finds the two votes recorded in motion tables and misses the votes recorded in sentences, such as "by a vote of 9:0". The dollar pattern assumes a leading `$`; budget documents that put negative values in parentheses need more. Test a pattern on several pages and several documents from the same source before you build on it, and count what it misses as well as what it finds.

## Words, Lines, and Tables with pdfplumber

pdfplumber, which is built on the pdfminer.six library, starts from where each character ends up rather than the order in which it was drawn. ### Finding Tables

A table in a PDF is characters that line up, usually with rules or shaded boxes around them, and pdfplumber's table finder rebuilds the grid. By default it uses the *lines* strategy: it collects the page's rules and the sides of its rectangles, joins those that nearly touch, and makes a cell wherever horizontal and vertical rules close a box. The *text* strategy infers columns from words that line up instead. Start with the summary page of the December 2024 report:

```{python}
import pandas as pd

def summary_frame(rows, columns, label="source"):
    """Turn the rows of a table of labeled figures into a DataFrame.

    Parameters
    ----------
    rows : list of lists
        The table, as pdfplumber's extract() or extract_table() returns it
    columns : dict
        Each column's name and its position in a row, such as {"source": 1, "ytd_2023": 3};
        every column but the label holds figures
    label : str
        The name, in columns, of the column that holds each row's label

    Returns
    -------
    pandas.DataFrame
        One row for each row with a label and a first figure; header rows and section titles are left out
    """
    # The figure columns: every column but the label, in the order columns lists them
    figure_columns = []
    for name in columns:
        if name != label:
            figure_columns.append(name)
    first_figure = figure_columns[0]

    records = []
    for row in rows:
        # Keep a row only if it has a label and a first figure; that leaves out headers and section titles
        if not row[columns[label]] or not row[columns[first_figure]]:
            continue
        record = {}
        for name, position in columns.items():
            record[name] = row[position]  # the cell in that column
        records.append(record)
    frame = pd.DataFrame(records)
    frame[label] = frame[label].str.replace("\n", " ")  # a label that wraps becomes one line
    for name in figure_columns:
        # Remove dollar signs, commas, and percent signs, then read what is left as a number
        frame[name] = pd.to_numeric(frame[name].str.replace(r"[$,%]", "", regex=True))
    return frame

# Where each column sits in fixed_rows: the label is the second cell, 2023 the fourth, and so on.
# For another table, name its own columns and positions; the label column defaults to "source"
summary_df = summary_frame(fixed_rows, {"source": 1, "ytd_2023": 3, "ytd_2024": 4, "change": 5, "pct_change": 7})
report.close()  # done with the December 2024 report's pages
print(summary_df[["source", "ytd_2024"]].to_string(index=False))

#                                     Construction Use Tax  14930902
```

**The table settings.** `find_tables()`, `extract_table()`, and `extract_tables()` all take the same dictionary of settings, and any setting you leave out keeps its default. The ones you are most likely to change, with their defaults in pdfplumber 0.11:

- **`vertical_strategy` and `horizontal_strategy`** (both `"lines"`) say where column and row boundaries come from:
  - `"lines"`: the page's rules and the sides of its rectangles;
  - `"lines_strict"`: rules only, ignoring rectangles, such as shaded backgrounds;
  - `"text"`: words that line up;
  - `"explicit"`: positions you give.
- **`explicit_vertical_lines` and `explicit_horizontal_lines`** (none): the positions, in points, for the `"explicit"` strategy, as the fix above used for the columns. They can also add boundaries to the ones another strategy finds.
- **`snap_tolerance`** (3 points): parallel rules closer than this are moved to one position, so that a border drawn twice, slightly apart, counts once. `snap_x_tolerance` and `snap_y_tolerance` set it for one direction.
- **`join_tolerance`** (3 points): pieces of a rule whose ends are this close are joined into one, so that a border drawn in segments counts as a single line.
- **`edge_min_length`** (3 points): rules shorter than this are dropped before the grid is built, which leaves out underlines and tick marks.
- **`intersection_tolerance`** (3 points): how close a horizontal and a vertical rule must come to count as crossing, and so to make the corner of a cell.
- **`min_words_vertical`** (3) and **`min_words_horizontal`** (1): for the `"text"` strategy, how many words must line up to make a column boundary or a row boundary. Raise `min_words_vertical` when a short run of aligned words makes a column that isn't there.
- **`text_x_tolerance`** and **`text_y_tolerance`** (3 points each): for the `"text"` strategy, how far apart letters can be and still count as one word, and how far up or down and still count as one line.

To see what a set of settings finds, draw it: `page.to_image().debug_tablefinder(settings)` outlines the cells and marks the crossings, as in @fig-missing-totals-row. pdfplumber's documentation lists every setting, with more on each: [Table-extraction settings](https://github.com/jsvine/pdfplumber#table-extraction-settings).

## When There Is No Text Layer: OCR

*Optical character recognition* (OCR) turns a picture of text into characters. An OCR engine finds the parts of a page that hold text, splits them into lines and words, and recognizes each character from its shape, using a model of the language to settle close calls. It works best on sharp, straight, high-contrast images of at least 300 dots per inch. [Tesseract](https://github.com/tesseract-ocr/tesseract), an engine that Hewlett-Packard built between 1985 and 1994, partly in Greeley, Colorado, and that Google developed from 2006, is the standard open-source choice. `pytesseract` runs Tesseract from Python; both were installed under "Installing pypdf, pdfplumber, and pytesseract", at the start of the chapter.

**A scanned page.** Page 7 of the December 4, 2018 minutes is the page where the scanner's own OCR garbled the motions ("What Kind of PDF Is It?"). The page is one image, which pypdf hands you as a Pillow image, and Tesseract reads that:

The figures are whole dollars, so commas and periods can both be dropped. A stray mark that breaks a row's pattern is harder, so set those rows aside and report them:

```{python}
NUMBER = r"[—–-]?\d[\d.,]*"  # a figure as OCR may read it, with a stray dash, or periods for commas
# A row: an optional category name, a year, then 13 figures (twelve months and the year's total)
ROW = re.compile(r"^(?P<label>[A-Za-z ]*?)\s*(?P<year>20\d\d)\s+(?P<figures>(?:" + NUMBER + r"\s+){13})")

def ocr_dollars(figure):
    """'8.832.480' -> 8832480. The table's dollar figures are whole and positive, so every other character can go."""
    return int(re.sub(r"\D", "", figure))  # \D: anything that isn't a digit

ocr_rows = []   # the rows that parsed
set_aside = []  # lines with a year that didn't parse
category = None # the tax the current rows belong to
for line in ocr_lines:
    match = ROW.match(line)
    if not match:
        if re.search(r"\b20\d\d\b", line):
            set_aside.append(line)  # a line with a year that didn't parse: keep it to look at
        continue                    # go on to the next line
    if match["label"].strip():
        category = match["label"].strip()  # each category's name starts its first row
    figures = []
    for figure in match["figures"].split():
        figures.append(ocr_dollars(figure))
    # The first twelve figures are the months, and the thirteenth is the year's total
    ocr_rows.append({"category": category, "year": int(match["year"]), "months": figures[:12], "total": figures[12]})

print(len(ocr_rows), "rows parsed;", len(set_aside), "set aside")
for line in set_aside:
    print(" ".join(line.split()[:6]))  # the start of each line set aside
# 28 rows parsed; 2 set aside
# ” 2022 489,417 405,726 646,263 552.449
# 2022 12,289,385 11,703,828 14,650,181 — 13,712,583
```

The table has four taxes and their total, each with a row for every year from 2019 to 2024: 30 rows. 28 parsed, and the two set aside each have a stray mark, `”` or `—`, that breaks the pattern. A parsed row can still be wrong, though, since a misread digit leaves a well-formed number. The table checks itself, because each row's twelve months add up to its total:

```{python}
# For each row, how far the twelve months' sum is from the printed total, in dollars either way

for row in ocr_rows:
    gap = abs(sum(row["months"]) - row["total"])

```

Every parsed row adds up within \$2, the rounding you'd expect. A digit misread anywhere but the last place would miss by \$10 or more.

## Checking an Extraction

Extraction fails without errors. pdfplumber dropped the summary table's totals row and raised nothing. The tally pattern found two votes and said nothing about the others. Tesseract read periods for commas, and its confidence scores flagged one such figure and passed another. Each of these was caught by a check, and checks are cheap: most take a line or two of code. Here they are, cheapest first, each with its example from this chapter:

1. **Look at the page beside the output.** The debug image showed where the table ended (@fig-missing-totals-row), and the scan of page 7 of the 2018 minutes showed that Tesseract read the motion right.
2. **Count.** You know how many rows the page shows. The summary table has nine rows of figures, Exhibit 3 has 30, and the council has nine seats.
3. **Types and ranges.** Every figure should parse as a number, and a value far outside the others gets a look. Exhibit 3 says that business use tax's taxable sales changed by 615.01% in 2019. The image says the same as the OCR, so the question goes to the city, not to Tesseract.
4. **Sums.** Parts should add up to their totals, within a tolerance for rounding. The summary table's five sources add up to \$171,006,200, and the subtotal printed beneath them is \$171,006,199.
5. **Two tools agree.** pypdf's text and pdfplumber's table, read from the same page, should give the same figures.
6. **Two documents agree.** OCR's 2024 total from Exhibit 3 should equal the summary page's, which is text. Reports that overlap should agree too: the December 2023 and December 2024 reports both print 2023's figures, and all 12 match.
7. **A sample coded by hand.** For text, such as the names in an attendance list, read a sample of pages yourself and measure the extraction against it.
8. **A record of what you did.** Keep the manifest of files and hashes, the versions of the libraries, and the date of each run, so that someone else can audit your work and redo it.

Write the checks as a function that returns a list of problems, so a pipeline can run them on every file and report what failed, instead of stopping at the first error or carrying on in silence:

```{python}
def check_summary(table, tolerance=5):
    """Check the revenue summary table's figures against each other.

    Parameters
    ----------
    table : pandas.DataFrame
        The table, from summary_frame()
    tolerance : int
        How many dollars a sum may miss by; the report rounds each figure to the dollar

    Returns
    -------
    list of str
        One line for each failed check; an empty list means every check passed
    """
    problems = []

    # Count: the page shows nine rows of figures
    if len(table) != 9:
        problems.append(f"expected 9 rows of figures, found {len(table)}")

    # Look up rows by their labels from here on
    figures = table.set_index("source")
    subtotal = "Total Sales & Use Tax based on current economic activity"
    total = "Total Sales and Use Tax"
    for label in [subtotal, total]:
        if label not in figures.index:
            problems.append(f"no row labeled {label!r}")
    if problems:
        return problems  # the sums below need every row

    # Sums, for each year: the parts should add up to the subtotal, and the subtotal and audits to the total
    for year in ["ytd_2023", "ytd_2024"]:
        sources = figures[year].iloc[:5].sum()  # the five sources above the subtotal
        if abs(sources - figures.loc[subtotal, year]) > tolerance:
            problems.append(f"{year}: the sources add up to {sources:,}, not {figures.loc[subtotal, year]:,}")
        audits = figures.loc["Sales Tax Audit Revenue", year] + figures.loc["Use Tax Audit Revenue", year]
        if abs(figures.loc[subtotal, year] + audits - figures.loc[total, year]) > tolerance:
            problems.append(f"{year}: the subtotal and audit revenue don't add up to the total")
    return problems

# The table as the default settings read it, which missed the totals row; its columns sit in other places
default_df = summary_frame(default_rows, {"source": 0, "ytd_2023": 2, "ytd_2024": 4, "change": 5, "pct_change": 6})
print("fixed table:  ", check_summary(summary_df))
print("default table:", check_summary(default_df))
# fixed table:   []
# default table: ['expected 9 rows of figures, found 8', "no row labeled 'Total Sales and Use Tax'"]
```

```{python}
def split_names(names):
    """Split a list of surnames such as "Speer, Wallach, and Winer" into a set."""
    names = re.sub(r"\b([A-Z]) ([a-z]+)", r"\1\2", names)  # pypdf's "S peer" is "Speer"
    surnames = set()
    # Split at each comma and at each word "and"
    for name in re.split(r",|\band\b", names):
        if name.strip():
            surnames.add(name.strip())
    return surnames

def roll_call(page_1):
    """Find the members present at a meeting's roll call.

    Parameters
    ----------
    page_1 : str
        The cleaned text of page 1 of a meeting's minutes

    Returns
    -------
    set of str
        The surnames of the members present, in the room or online
    """
    present = set()

    # The mayor calls the meeting to order; through 2020, the list of members leaves the mayor out
    mayor = re.search(r"Mayor (\w+) called the meeting to order", page_1)
    if mayor:
        present.add(mayor.group(1))

    # 2018-2020: "Council Members Brockett, Carlisle, ... and Young were present"
    sentence = re.search(r"Council Members ([A-Z][^:]*?)\s+were\s+present", page_1)
    if sentence:
        present |= split_names(sentence.group(1))  # "|=" adds the names to the set

    # 2021-2024: "Council Members present: ...", "Virtually present: ...", "Present virtually: ..."
    lines = page_1.splitlines()
    for i, line in enumerate(lines):
        label = re.match(r"(?:.*Members present(?: virtually)?|Virtually present|Present virtually):\s*(.*)", line, re.IGNORECASE)
        if label:
            names = label.group(1)  # the names after the label, on this line
            for following in lines[i + 1:]:
                if not names.endswith(","):
                    break  # a list that goes on to the next line ends this one with a comma
                names += " " + following
            present |= split_names(names)
    return present
```

### Reading the Totals Row by Position

"Finding Tables" showed that pdfplumber's table finder leaves out the totals row on the December 2024 page, because the row has no vertical rules beside it. The other reports' tables have different rules, and each would need its own settings. One row is all this question needs, though, and pdfplumber can find a row without finding the table: `search()` returns where a phrase sits on the page, and a crop of the page from the left edge to the right, as tall as that line, holds the row's words. The column headings work the same way: the two years sit side by side above the figures.

```{python}
def row_words(page, label):
    """Return the words to the right of label, on the line where label is.

    Parameters
    ----------
    page : pdfplumber.page.Page
        The page to read
    label : str
        A regular expression for the row's label, such as "Total Sales and Use Tax"

    Returns
    -------
    list of str
        The row's other words, from left to right
    """
    found = page.search(label)[0]  # the first match: its text, and its position in points
    # A strip of the page, across its whole width, from just above the label to just below it
    line = page.crop((0, found["top"] - 1, page.width, found["bottom"] + 1))
    words = []
    for word in line.extract_words():
        if word["x0"] > found["x1"]:  # the word starts right of where the label ends
            words.append(word["text"])
    return words

def to_number(text):
    """Turn a figure such as "$134,538,892", "(1,145,528)", or "-$1,608,698" into an int."""
    negative = text.startswith(("(", "-"))   # accountants write a negative number in parentheses
    value = int(re.sub(r"[^\d]", "", text))  # keep only the digits
    if negative:
        return -value
    return value

with pdfplumber.open(get_saved_copy("revenue-report-2018.pdf")) as pdf:
    page = find_summary_page(pdf)
    # Two years side by side, such as "2017 2018"; "groups" holds what each pair of parentheses matched
    print(page.search(r"(20\d\d) +(20\d\d)")[0]["groups"])
    print(row_words(page, "Total Sales and Use Tax"))
# ('2017', '2018')
# ['$134,538,892', '$140,648,710', '$6,109,818', '4.54%']
```

## Document Understanding

Everything so far rebuilds a page step by step, and you choose each step: which library reads the text layer, where a table's columns are, which rows to set aside. *Document understanding* is the research field that tries to read a document as a whole. Its tasks include *layout analysis*, which finds the headings, paragraphs, tables, and figures on a page and the order to read them in; *table structure recognition*, which finds a table's rows, columns, and merged cells; OCR; and *key information extraction*, which pulls named fields, such as a date or a total, out of forms and invoices. The [Awesome Document Understanding](https://github.com/tstanislawek/awesome-document-understanding) list collects the field's papers, datasets, and tools.

Its tools usually write Markdown or HTML, because those formats keep a document's structure, its headings, lists, and tables, as text that a script or a language model (@sec-ai-apis) can read.

### Three Kinds of Tools

- **Converters that read the text layer.** [MarkItDown](https://github.com/microsoft/markitdown), from Microsoft, turns PDFs, Word, PowerPoint, Excel, and HTML files into Markdown. For a PDF it reads the text layer, much as pypdf does, so it is fast and needs no model, but a scanned page gives it nothing to read. [pymupdf4llm](https://github.com/pymupdf/pymupdf4llm) is similar; note its AGPL license, which has conditions for software you distribute.
- **Pipelines of models.** A layout model finds the parts of each page, a table model finds each table's cells, and an OCR engine reads any part that is a picture. [Docling](https://docling.ai/), which IBM Research started and the LF AI & Data Foundation now hosts, runs on a laptop's processor. [Marker](https://github.com/datalab-to/marker), from Datalab, and [MinerU](https://github.com/opendatalab/MinerU), from OpenDataLab, work the same way, with a GPU for their best modes.
- **Vision-language models.** A model reads an image of the page and writes the whole page out as Markdown or HTML, tables included. Most need an NVIDIA GPU: [olmOCR](https://github.com/allenai/olmocr) from Ai2, [DeepSeek-OCR](https://github.com/deepseek-ai/DeepSeek-OCR), [Chandra](https://github.com/datalab-to/chandra) from Datalab, [dots.mocr](https://github.com/rednote-hilab/dots.ocr), and [PaddleOCR-VL](https://github.com/PaddlePaddle/PaddleOCR). [LightOnOCR-2](https://huggingface.co/lightonai/LightOnOCR-2-1B), at one billion parameters, is small enough to run, slowly, without one. Hosted services, such as [Mistral OCR](https://docs.mistral.ai/studio/document-processing/basic_ocr) and Datalab's own API, run the model for you, for a fee per page, after you upload the document.

[Pandoc](https://pandoc.org/) belongs beside these tools but does a different job. It converts between markup formats, such as Markdown, HTML, Word, LaTeX, and EPUB, and Quarto uses it to build this book. Pandoc can write a PDF but can't read one, so it comes after a parser: `pandoc -s summary.md -o summary.html` turns a parser's Markdown into a web page, and `-o summary.docx` into a Word file.

On Exhibit 1 it mixed the two: a few rows came out as Markdown tables, some of them tables of a single row, the rest as lines of text, with empty tables in between. Exhibit 3, the picture of a table, gave only the note beside it, because MarkItDown doesn't run OCR unless you connect it to a language model or to Microsoft's cloud service.

**Docling** took about 20 seconds for the summary page and wrote a Markdown table with all nine rows of figures, the totals row included, which pdfplumber's default settings missed. It named each column from the header above, such as "December YTD - 2024". On the picture of Exhibit 3 it ran its default OCR engine, RapidOCR, whose models it downloaded first, and took about a minute. It read "7,608,759", where Tesseract wrote "7,608.759". But the chapter's checks found what else went wrong:

- **Sums.** Of the table's 30 rows of figures, 21 came out whole, and every one of those adds up to its total.
- **Count.** The other nine didn't come out whole. Two years' rows were merged into one, with two figures in each cell; one row lost most of its figures; others had empty cells.
- **Labels.** Two rows that pass the sums carry the wrong label: Docling put "Change from prior year (YTD)" beside Construction Use Tax's 2019 figures, and the TOTAL label on an empty row below the total's 2019 figures. Sums can't catch a wrong label, so check the labels as well.

Nothing raised an error. The table looked complete, and only the checks showed which rows to trust.

### Judging a Parser

A parser's benchmark score, such as [olmOCR-Bench](https://arxiv.org/abs/2502.18443) or OmniDocBench, says how it did on other people's documents, usually as its own makers report it. On your documents, run the checks from "Checking an Extraction": count the rows, add up the parts, compare two tools, and code a sample by hand. Then weigh what else the tool costs:

- **Privacy.** A hosted service receives your document. So does a local tool when you switch on its cloud options, such as MarkItDown's language-model and Microsoft Azure features, Marker's `--use_llm`, or MinerU's remote mode. Don't upload records that hold personal information without permission.
- **Plausible errors.** A vision-language model writes text that looks right. Where Tesseract garbles a digit, a model can write a different, well-formed number, or fill in a cell it couldn't read. Sums and second printings catch these; reading the output does not.
- **Reproducibility.** Record the tool's version and the model's, as the chapter does for pypdf and pdfplumber. A model that changes can change your data.
- **Time and cost.** Docling took a minute for one picture of a table on a laptop's processor. A thousand pages takes hours without a GPU, or a fee per page from a hosted service.

For the two case studies, the chapter's own code was the better choice: pypdf and pdfplumber read the text layer exactly, and each step can be checked. Reach for a parser when documents have no text layer, come in many layouts, or are too many to write patterns for, and run the checks on what it produces.

## Social History and Public Interest

The PDF format was created by Adobe in 1993 to solve a real problem: documents needed to look the same regardless of what printer or screen displayed them. But the format's emphasis on visual fidelity came at the cost of semantic accessibility. Organizations like DocumentCloud, MuckRock, and the Sunlight Foundation have built tools to extract structured data from the flood of PDFs that government agencies produce — bridging the gap between nominally public records and practically accessible data.

DocumentCloud, built by ProPublica and IRE (Investigative Reporters and Editors), emerged as a platform where journalists could upload, analyze, annotate, and share document collections. It has been used in investigations of police misconduct records, corporate fraud filings, and government secrecy — cases where the raw documents are public but the volume makes manual analysis impractical. DocumentCloud's contribution was not just technical but organizational: it created a shared infrastructure where one journalist's document processing work could benefit others investigating the same institutions.

MuckRock took a different approach to the document access problem by automating the Freedom of Information Act (FOIA) request process itself. The platform helped journalists and citizens file thousands of public records requests, tracked agency response times, and published the results openly. The Sunlight Foundation, active from 2006 to 2020, advocated for government agencies to publish documents in machine-readable formats rather than PDFs in the first place — arguing that true transparency requires not just publication but *usability*. Together, these tools and organizations represent the infrastructure of transparency: community-built resources that bridge the gap between nominally public documents and practically accessible data. Their work embodies the **ownership** value from @sec-post-api — the idea that public records belong to the public, and that technical barriers to access are themselves a form of enclosure that undermines democratic accountability.

The Boulder City Council case illustrates this tension at the local level. The same meeting information could be published as structured data (allowing citizens to easily track attendance, voting patterns, and public comment frequency) or as scanned PDFs (requiring significant technical effort to analyze). The format choice is itself a policy decision with consequences for transparency and accountability. When you build a pipeline that extracts structured data from PDFs, you are not just doing data science — you are doing the work that these organizations have championed for decades.

## Common Issues to Debug

- **Garbled text from scanned PDFs**: PyPDF extracts text only from PDFs that have a text layer. Truly scanned documents require OCR tools like Tesseract.
- **Table data extracted as a text stream**: PyPDF is not a table extraction tool. For tabular data in PDFs, consider `pdfplumber` or `camelot`.
- **Regular expressions that work on one document but fail on another**: PDF formatting varies even within documents from the same source. Test your patterns on multiple files.
- **Encoding issues**: Some PDFs use non-standard character encodings. Use `.encode('utf-8', errors='replace')` if needed.

## Key Takeaways

PDFs are designed for visual fidelity, not data extraction. pypdf gives you a page's text in the order it was drawn; pdfplumber gives you where each word sits, which is what a table needs; and regular expressions impose structure on what either extracts. Expect messiness — PDF extraction is reconstruction, not reading — and check every extraction: against a sample coded by hand, against a second tool, against the document's own totals, and against a second printing of the same figure. The broader lesson connects to @sec-post-api: when institutions publish data only in PDF form, they create a practical barrier to the analysis that nominally public records are meant to enable.

## Appendix: Technical Notes

These notes cover three things the chapter mentions and sets aside: why the city's server needs a certificate bundle, how to check that two copies of a file are the same, and how to add a text layer to a whole scanned PDF.

### The City's Server and Its Certificate

Your first request to Boulder's portal from Python will probably fail with `SSLError: … CERTIFICATE_VERIFY_FAILED … unable to get local issuer certificate`. A server proves who it is with a chain of certificates: its own, signed by an *intermediate* certificate, which is signed by a *root* certificate that your computer already trusts. Boulder's server sends its own certificate but not the intermediate one. Browsers find the missing certificate by themselves; Python doesn't.

`verify=False` would make the error go away by turning off the check that you're talking to the real server, so don't use it. The book's bundle, `boulder-ca-bundle.pem`, holds the standard root certificates plus that one intermediate, and `verify=bundle` tells `requests` to check the server against it. If the city repairs its server, the bundle still works. `data/ch-09/make_ca_bundle.py` in the book's repository shows how the bundle was made.

### Checking That Two Copies Are the Same File

A *hash* is a fingerprint of a file's bytes: change one byte and the hash changes. `data/ch-09/manifest.csv` records each saved copy's hash, along with its address on the portal and when it was downloaded. Comparing a file's hash with the manifest's says whether you have the same file, byte for byte. If you have run the chapter's cells in order, you have 18 of the manifest's 20 files:

```{python}
import hashlib

manifest = pd.read_csv(get_saved_copy("manifest.csv"))  # one row per saved file
checked = 0
differ = []
for row in manifest.itertuples():
    path = PDF_DIR / row.file
    if not path.exists():
        continue  # check only the files you have downloaded
    digest = hashlib.sha256(path.read_bytes()).hexdigest()  # the file's SHA-256 hash, as text
    checked += 1
    if digest != row.sha256:
        differ.append(row.file)
print(checked, "files checked; hashes that differ:", differ)
# 18 files checked; hashes that differ: []
```

To check a fresh download from the portal, compute `hashlib.sha256(response.content).hexdigest()` and compare it with the file's row. The two scanned minutes from 2000 are the exception: the portal builds a new PDF from their page images for every download, so no two downloads have the same hash.

### OCR for a Whole File: OCRmyPDF

pytesseract returns text and leaves the PDF as it was. [OCRmyPDF](https://ocrmypdf.readthedocs.io/) does the whole file: it renders each page, runs Tesseract, and lays the recognized text over the image as an invisible layer, where a viewer can select it and pypdf can extract it.

It is harder to install than the libraries in this chapter, because it is a program that runs other programs, Tesseract among them, and chapter 1's `webdata` leaves it out. In `webdata`, `conda install -c conda-forge ocrmypdf` may be all it takes. If that fails, or OCRmyPDF reports a missing program, follow its [installation guide](https://ocrmypdf.readthedocs.io/en/latest/installation.html), which gives the steps for each system: Homebrew (`brew install ocrmypdf`) or MacPorts (`sudo port install ocrmypdf`) on a Mac, the package manager on Linux, and several steps on Windows.

The minutes of December 19, 2000, which the portal made from scanned pages, have text on only three of their nine pages. `mode="redo"` replaces any earlier OCR layer and fills in the pages without one:

```{python}
import ocrmypdf

scan_2000 = get_saved_copy("council-minutes-2000-12-19.pdf")
ocr_copy = PDF_DIR / "council-minutes-2000-12-19-ocr.pdf"  # where to save the new copy
# OCR every page in English, and write a copy with a text layer
ocrmypdf.ocr(scan_2000, ocr_copy, language="eng", mode="redo", progress_bar=False)

# Characters of text on each page, before and after
before = []
for page in PdfReader(scan_2000).pages:
    before.append(len(page.extract_text()))
after = []
for page in PdfReader(ocr_copy).pages:
    after.append(len(page.extract_text()))
print("characters per page before:", before)
print("characters per page after: ", after)
# characters per page before: [2207, 0, 0, 0, 1693, 1575, 0, 0, 0]
# characters per page after:  [2270, 1698, 1663, 1465, 1709, 1597, 1751, 2283, 1164]
```

It takes a few seconds. To find out whether it read the pages right, compare its text with the image, by hand, for the lines you need:

```{python}
# Deputy Mayor Mock called the regular December 19, 2000 meeting of the Boulder City
```
